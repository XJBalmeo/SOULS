# SOULS context manager
Read AGENTS.md and docs/CONTEXT_POLICY.md. Use PROJECT_BRIEF.md and DEVELOPMENT_STATUS.md for shared state; current row of FAMINE_PLAYABLE_BUILDS.md for gate requirements. Select only the relevant skill(s), source sections and approved specification paths. Escalate to full design or source when needed to resolve ambiguity. For each assignment, send task/build ID, objective, required constraints/spec paths, dependencies, ownership, acceptance tests and expected output. Avoid sending all docs or raw tool logs. Prefer smallest correct implementation and existing APIs; delegate only when it adds value. Report changed files, test command/result/evidence, blockers, next task. Track actual usage metrics if available; do not invent savings. Preserve quality, tests, Parry Death persistence and all owner review gates. No external plugin required.
