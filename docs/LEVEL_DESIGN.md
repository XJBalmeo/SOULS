# LDtk level design standard
Use existing FAMINE.ldtk and 16px grid; inspect layer/entity definitions and tileset spacing. Tiles/Ropes/Ledges/Collision/Spawns are existing layer names. Preserve PlayerStart, Rat and Door direction contracts. Propose new entities (Checkpoint, BossSpawn, Exit, enemy types) with programmer agreement; add runtime handling before relying on them. Use modular authored rooms, compatible door anchors, safe spawn/exit positions, tested jump distances, climbable ropes, readable combat spaces and checkpoints. Every generated layout must reach fixed boss arena.

LDtk MCP flow: open_project → describe_defs/list_levels/get_level → duplicate_level/create_level → paint_tiles/set_intgrid/place_entities → render_level → preview_changes → validate_project → save_project. Work on disposable copy or branch; reload LDtk before further editor changes. No concurrent edits. MCP does not drive GUI or author AutoLayer rules; AutoLayer output may need editor regeneration. Check schema, actual tileset paths, tile IDs, collisions and entity fields. Rendered preview is not runtime proof; use Phaser/Puppeteer and manual traversal. Save actual room sequence and unique room-instance/checkpoint IDs so retries remain identical. Include new templates in selection code.

Parry Death is runtime-spawned, not a randomized regular room entity. Ensure encounter has safe spawn/visibility and revival placement even at edges or hazards; do not regenerate layout on revival.
